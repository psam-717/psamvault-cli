# Configuration reference

Every file, path and environment variable psamvault uses, and what each one is for.

## psamvault layout

Everything psamvault writes under your home directory:

| File | Purpose |
|---|---|
| `~/.psamvault/config.env` | Non-sensitive API URL only |
| `~/.psamvault/session.json` | Empty presence marker `{}` — no secrets |
| `~/.psamvault/flask_sessions/` | Server-side Flask session data (VEK, tokens) — permissions `0700` |
| `~/.psamvault/policy.json` | Reveal policy — `human-only` (default), `strict` or `open`. Absent means the safe default |
| `~/.psamvault/audit.jsonl` | Every reveal decision: who asked, the matched signal, allow/deny. Owner-only, rotated at ~1 MB, never contains a secret |

All sensitive values (pepper, tokens, VEK) live exclusively in the OS keychain or in the server-side session directory. The recovery kit file (`psamvault-key-<date>.json`) is written where you point it — the Desktop by default — never inside `~/.psamvault`.

Both `.json` and `.env` files are restricted to owner read/write only (`chmod 600`). The `flask_sessions/` directory is restricted to owner (`chmod 700`).

Three more files appear in the same directory as psamvault runs:

| File | Purpose |
|---|---|
| `~/.psamvault/flask_secret_key` | The dashboard's Flask secret key, generated on first `psamvault dashboard` and re-read on later starts (owner-only) so session IDs survive a server restart |
| `~/.psamvault/last_seen_version` | The version whose changelog notice has already been shown, so the notice is not repeated on every command |
| `~/.psamvault/backups/backup-<UTC stamp>/` | Pre-update snapshots of `session.json` and `last_seen_version`, taken by the source-track upgrade. At most the 5 most recent are kept |
| `~/.psamvault/audit.jsonl.1` | The single previous generation of the audit trail, created when `audit.jsonl` reaches ~1 MB |

The directory itself is created `0700`.

## Per-OS paths

| | Windows | macOS | Linux |
|---|---|---|---|
| State directory | `%USERPROFILE%\.psamvault` | `~/.psamvault` | `~/.psamvault` |
| Secret store | Windows Credential Manager | macOS Keychain | Secret Service |
| Default kit / export location | `%USERPROFILE%\Desktop\…` | `~/Desktop/…` | `~/Desktop/…` |
| File permissions | Owner-only, best effort (`chmod` is a no-op) | `chmod 600` / `700` enforced | `chmod 600` / `700` enforced |

The kit path falls back to your home directory on a machine that has no `Desktop` folder:

| OS | Default kit path |
|---|---|
| Windows | `%USERPROFILE%\Desktop\psamvault-key-<date>.json` |
| macOS / Linux | `~/Desktop/psamvault-key-<date>.json`, or `~/psamvault-key-<date>.json` when there is no Desktop folder |

Windows reports one permission mode for every file regardless of its ACLs, which is why the policy *file permission* warning is POSIX-only rather than noisy and useless there.

## The OS keychain

All sensitive session and config values are stored in the OS keychain — never written to disk in plaintext:

| Value | Keychain key |
|---|---|
| HMAC pepper | `psamvault / config.pepper` |
| Access token (JWT) | `psamvault / session.access_token` |
| Refresh token | `psamvault / session.refresh_token` |
| KDF salt | `psamvault / session.kdf_salt` |
| Vault Encryption Key | `psamvault / session.vek` |
| Encrypted VEK (server copy) | `psamvault / session.encrypted_vek` |
| VEK IV | `psamvault / session.vek_iv` |

The service name is `psamvault` in every case. The same keychain service also holds the one-shot agent approval tokens minted by `psamvault approve` (a live-token index plus one row per token), which is why `psamvault logout` can drop them: no approval outlives the session it was minted for.

The access token is a short-lived JWT (15 min) and the refresh token is a long-lived opaque token (30 days). psamvault refreshes the access token before it expires, so you are not prompted mid-command.

## Environment variables

| Variable | Read / written by psamvault | Meaning |
|---|---|---|
| `PSAMVAULT_API_URL` | read (and written to `config.env` by `psamvault configure`) | Base URL of the backend API. Default when unset: `https://psam-vault-backend.onrender.com` |
| `PSAMVAULT_PEPPER` | read (kept in the OS keychain, loaded into the environment at start-up) | The device's HMAC pepper. Generated by `psamvault configure`; never sent to the server |
| `PSAMVAULT_AGENT` | set by psamvault | Declares this process an agent caller. Set by the global `--agent` flag, and exported by the MCP server into the subprocesses it spawns |

Two rules govern them:

- **Both `PSAMVAULT_API_URL` and `PSAMVAULT_PEPPER` must be present** for the machine to count as configured. `psamvault configure` is what establishes both.
- **A real environment variable always wins over the config file.** A value in `config.env` only fills in what the environment has not already set. A pepper found *inside* `config.env` (an old install) is moved to the keychain and removed from the file on the next run.

### Variables the reveal guardrail reads

These are not psamvault settings — psamvault only reads them, to work out who is calling. Set them only if you are an integration declaring itself; the whole design is described in [The agent reveal guardrail](../guides/agent-reveal-guardrail.md).

| Variable | Set by | Effect |
|---|---|---|
| `PSAMVAULT_AGENT` | you, or `--agent`, or the MCP server | Explicit agent declaration: reveal commands are refused |
| `AI_AGENT` | Hermes | Host marker — any non-empty value counts |
| `HERMES_AGENT` | Hermes | Host marker — truthy value (`1`/`true`/`yes`/`on`) |
| `CLAUDECODE` | Claude Code | Host marker — truthy value |
| `CLAUDE_CODE_ENTRYPOINT` | Claude Code | Host marker — any non-empty value counts |
| `TERMINAL_CWD`, `TERMINAL_ENV` | the Hermes terminal tool | Host markers — any non-empty value counts |
| `CI` | your CI runner | Recorded as `env:CI` in the audit row. A truthy `CI` does **not** by itself make the caller an agent — a bare CI job is allowed and audited under `human-only`, and refused under `strict` |

## policy.json

`~/.psamvault/policy.json` — absent means the safe default, so a fresh machine is protected with nothing to configure. The same file works on Windows, macOS and Linux; the permission warning (`chmod 600`) is POSIX-only, since Windows reports one mode for every file and uses your user ACL instead.

```json
{ "reveal": "human-only", "allow_entries": ["github.com"], "approval_ttl_seconds": 120, "audit": true }
```

| Key | Type | Default | Meaning |
|---|---|---|---|
| `reveal` | string | `"human-only"` | One of `"human-only"`, `"strict"`, `"open"` |
| `allow_entries` | list of strings | `[]` | Per-entry allowlist for agents — a long-running job that needs one specific secret. Matched case-insensitively against the exact entry name |
| `approval_ttl_seconds` | integer | `120` | How long a `psamvault approve` token stays live. Coerced into the supported window: **15–3600** seconds |
| `audit` | boolean | `true` | Whether reveal decisions are recorded |

| `"reveal"` | An agent (markers, ancestry) | A bare pipe, script or CI job | |
|---|---|---|---|
| `"human-only"` *(default)* | refused | allowed + audited | stops the real case without breaking your pipes or CI |
| `"strict"` | refused | refused | "no terminal, no secret" — you opt in |
| `"open"` | allowed + audited | allowed + audited | everything works; the trail still records it |

`allow_entries` is a per-entry allowlist for agents — useful when a long-running
job needs one specific secret. A malformed policy file falls back to the safe
defaults with a warning rather than crashing the CLI.

What a bad file does, precisely:

| Problem | Result |
|---|---|
| File absent | Safe defaults, no warning |
| Not valid JSON | Safe defaults + a warning naming the file |
| JSON that is not an object | Safe defaults + a warning |
| Unknown `reveal` value | `human-only`, with a warning naming the bad value |
| `allow_entries` not a list | Ignored, with a warning |
| `approval_ttl_seconds` out of range or not a number | Clamped to 15–3600, or reset to the default of 120 |
| Unreadable file | Safe defaults + a warning |
| POSIX group/other permission bits set | A warning telling you to `chmod 600` |

A typo never makes the vault unusable and never silently opens it: the CLI falls back to the safe defaults and says so.

## audit.jsonl

Forensics for the reveal guardrail, one JSONL row per decision, `0600`, rotated to `audit.jsonl.1` at ~1 MB:

```json
{"ts": "...Z", "command": "get", "entry": "github.com", "caller": "agent", "signals": ["marker:AI_AGENT=hermes-agent"], "tty": false, "pid": 1234, "ppid": 1200, "decision": "deny", "token_id": null, "policy": "human-only"}
```

| Field | Meaning |
|---|---|
| `ts` | UTC timestamp of the decision |
| `command` | The gated action: `get`, `ak-get`, `note-get`, `export --plaintext`, or `approve` |
| `entry` | The entry the reveal was for, or `null` for a whole-vault dump |
| `caller` | The verdict: `human`, `uncertain` or `agent` |
| `signals` | The evidence that matched, e.g. `marker:AI_AGENT=hermes-agent`, `explicit:PSAMVAULT_AGENT`, `env:CI`, or an ancestry match |
| `tty` | Whether both stdin and stdout were terminals |
| `pid`, `ppid` | The process and its parent, for correlating a denial with the thing that asked |
| `decision` | `allow`, `deny`, `approved` (an agent's reveal consumed a token) or `minted` (a human authorised one) |
| `token_id` | The approval token involved, or `null` |
| `policy` | The effective `reveal` mode at the time |

Two invariants hold for every row, and both are pinned by tests:

- **A row never contains a secret.** Only names, ids, verdicts and signal names are written — never a value read out of the vault. The file is meant to be greppable and shareable.
- **Auditing never breaks a command.** Any I/O failure is swallowed, because a read-only home directory must not stop you reading your password. The honest consequence is stated in `SECURITY.md`: a full disk or a hostile `~/.psamvault` can silence the trail, which is why the trail is evidence of *well-behaved* callers, not tamper-proof logging.

## Kit files and exports

Neither of these lives in `~/.psamvault`:

| File | Written by | Contains |
|---|---|---|
| `psamvault-key-<date>.json` | `psamvault backup create` / `rotate` (Desktop by default, or `--out`) | Key material only — no entry plaintext, no ciphertext, no pepper, no passphrase. `0600` |
| `psamvault-backup-<date>.json` | `psamvault export` / `psamvault uninstall` (Desktop) | The entries themselves, encrypted with an export passphrase |
| `psamvault-backup-plaintext-<date>.json` | `psamvault export --plaintext` (Desktop) | The entries as readable JSON. Testing only |

The kit file and the data dump cover different disasters — see [Backup vs. data dump](../guides/backup-and-recovery.md#backup-vs-data-dump).
